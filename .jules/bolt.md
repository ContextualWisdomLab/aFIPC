## 2024-07-04 - R 언어에서 루프 내 데이터 프레임 탐색 병목 최적화

**Performance Issue:** `which(df$column == val)`을 루프 내부에서 반복적으로 호출하면
루프마다 전체 데이터 프레임을 스캔하여 O(N)의 성능 저하가 발생합니다.
**Optimization:** `split(seq_len(nrow(df)), df$column)`을 사용하여 루프 밖에서 미리
인덱스를 계산하고 캐싱하면, 리스트를 통한 O(1) 조회가 가능해집니다.

## 2024-07-07 - R 언어에서 데이터 프레임의 특정 항목 탐색을 캐싱하여 O(N) 검색 병목 최적화

**Performance Issue:** 루프 내부에서 조건에 맞는 서브셋을 반복적으로 생성하면 (예:
`subset <- df[df$id == item_id, ]`) 매 반복마다 O(N) 시간 복잡도의 전체 스캔이
발생합니다.
**Optimization:** `split()` 함수를 사용하여 데이터 프레임을 그룹화된 리스트로 변환하고
캐싱하여 O(1) 시간 복잡도로 빠르게 리스트에 접근할 수 있게 합니다.

## 2024-07-08 - R 언어에서 루프 내 인덱스 검색(which) O(N) 병목 최적화

**Performance Issue:** `which(df$col == val)`을 루프 내부에서 반복적으로 호출하면 루프마다
전체 데이터 프레임을 스캔하여 O(N)의 성능 저하가 발생합니다.
**Optimization:** 루프 밖에서 매칭되는 행의 리스트 인덱스를 캐시(`split()` 사용)하면,
O(1)의 리스트 조회가 가능하여 O(N) 성능 병목을 제거할 수 있습니다.

## 2026-07-11 - R 언어에서 루프 내 벡터 동적 확장 및 조건부 탐색 최적화

**Performance Issue:** 루프 내부에서 `which(vec == val)`을 호출하여 반복적으로 인덱스를
스캔하거나 빈 벡터(`c()`)에 원소를 동적으로 추가하는 방식은 O(N^2)의 성능 저하를 유발합니다.
**Optimization:** 스캔할 인덱스를 `match()` 또는 `split()`을 통해 미리 계산하고, 결과를
저장할 리스트를 `vector("list", N)`으로 사전 할당하여 불필요한 메모리 재할당과 전체
스캔을 방지합니다.

## 2024-07-12 - R 언어에서 데이터프레임 서브셋팅 시 불필요한 which() 및 반복 평가 제거

**Performance Issue:** 데이터프레임에서 조건부 값 할당 시 `which(df$col == val)`로
인덱스를 추출하거나 루프에서 같은 조건을 반복 평가하면 불필요한 함수 오버헤드와 O(N) 전체
스캔이 중복 발생합니다.
**Optimization:** `df$col == val` 형태의 직접적인 논리 인덱싱(logical indexing)을
사용하여 `which()` 오버헤드를 줄이고, 동일 조건으로 여러 열이나 행에 접근할 때는 불리언
인덱스 벡터(`idx <- df$col == val`)를 미리 캐싱해 O(N) 연산을 1회만 수행하도록 최적화합니다.

## 2025-02-12 - R 언어에서 반복적인 mirt 모델 생성 시 불필요한 데이터프레임 부분집합 추출 최적화

**Performance Issue:** 동일한 조건(예: 응답 데이터와 문항 타입)으로 여러 차례 `mirt()` 모델을
적합할 때 매번 원본 데이터프레임의 서브셋을 재생성하고 다시 필터링하면 불필요한 복사 및 처리
시간이 발생합니다.
**Optimization:** 한 번 생성된 mirt 모델 객체의 내부 슬롯(`model@Data$data`)에
캐시된 데이터 매트릭스를 재사용함으로써, 이후의 모델 생성 및 모수 추출 과정에서 중복 연산을
방지하여 성능을 높일 수 있습니다.
